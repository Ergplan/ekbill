# Architecture

EkBill v2 is an npm-workspaces monorepo. The master prompt (`docs/MASTER-PROMPT.md`) is the specification; this document describes what exists.

## Components

| Component   | Path              | What it is                                                                                                                                                                                                                                                                                                               |
| ----------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Web app     | `apps/web`        | Next.js 16 App Router, React 19. Screens, server actions (writes), route handlers (files, health). No business rules.                                                                                                                                                                                                    |
| Worker      | `apps/worker`     | pg-boss on the same Postgres. Stage 0: a heartbeat queue. Later: read-bill, render-other-sizes, index-search, reminders-due, backup-check.                                                                                                                                                                               |
| Engine      | `packages/engine` | Pure, deterministic: money, dates, ids, the rule pack (`rules/gst/*.json`, zod schema), tax, assess, numbering, issue, workings, bill form and guards, contract, language and phone. ESLint and `tests/unit/engine-purity.test.ts` forbid `node:`, `pg`, drizzle, `@ekbill/ai`, `fetch`, `Date.now`, `Math.random` here. |
| Database    | `packages/db`     | Drizzle schema (`src/schema.ts`), plain SQL migrations (`migrations/NNNN_*.sql`) applied by `migrate.mjs` under an advisory lock, repositories (Stage 2 onward). The one place that writes the database.                                                                                                                 |
| Models      | `packages/ai`     | Every model call: typed input/output, versioned prompts, retries, timeouts, one `ai_calls` row per call (Stage 7 onward).                                                                                                                                                                                                |
| Copy        | `packages/copy`   | `t(key, params, locale)` over `design/copy/strings.json` (`hi-Latn` default, `en` toggle).                                                                                                                                                                                                                               |
| Render      | `packages/render` | HTML → PDF/JPEG through Chromium, paper sizes (Stage 6).                                                                                                                                                                                                                                                                 |
| UI kit      | `packages/ui`     | The components of `design/components.md` plus v2's additions, tokens only, both themes. `/kit` renders them all.                                                                                                                                                                                                         |
| Design pack | `design`          | Workspace package `@ekbill/design`: tokens (`tokens.json` → `themes.css`, `tokens.ts` via `build.py`), fonts, copy, fixtures, reference screens.                                                                                                                                                                         |

## Data model

| `users`             | A person who signs in: phone, name, theme, language                                                                                                                                                                                                                                                                                                                      | `repos/users.ts` (own row: setTheme, setLanguage, setName), `memberships.invite` (a new person), the seed                                        | no business data; no RLS                                                                         |

| `items`             | What is usually on the bills: name (unique per business, case aside), HSN/SAC, unit, rate, GST rate, price includes tax, archived                                                                                                                                                                                                                                        | `repos/items.ts`, the seed                                                                                                                       | RLS; audited; delete refused                                                                     |

| `import_files`      | The uploaded files as bytes (≤ 8 MB), for the worker to read                                                                                                                                                                                                                                                                                                             | `repos/imports.ts#startImport`                                                                                                                   | RLS; audited without the bytes; immutable                                                        |
| `import_rows`       | One customer found (I6: staging only), the customer it already is, the customer the owner's tick made                                                                                                                                                                                                                                                                    | `repos/imports.ts#recordReading`, `#commitImport` (the link only)                                                                                | RLS; audited; the reading immutable                                                              |
| `series`            | A numbering series (I3): kind bill or credit_note, prefix, padding, include_fy, next_number, fy, active                                                                                                                                                                                                                                                                  | `repos/series.ts` (createSeries, updateSeries), `repos/documents.ts#issueDocument` (the allocation, row locked), the seed                        | RLS on `business_id`; audited; delete refused                                                    |
| `documents`         | A bill or credit note: draft, then issued (number, financial_year, issued_at, issued_snapshot, totals, the engine's lines), or cancelled; customer columns and the linked document                                                                                                                                                                                       | `repos/documents.ts` only: createDraft, updateDraft, issueDocument (the one writer of `status = 'issued'`, I2), cancelDocument, createCreditNote | RLS on `business_id`; audited; delete refused; `issue_gate` and `immutable_once_issued` triggers |
| `memberships`       | Who acts for a business and as what (owner, staff, accountant); one active owner per business                                                                                                                                                                                                                                                                            | `repos/memberships.ts` (invite, remove), `businesses.createBusiness` (the owner), the seed                                                       | read before a scope exists (resolveScope): no RLS; audited                                       |
| `sessions`          | A signed-in device: user, the business and role it acts as, expiry                                                                                                                                                                                                                                                                                                       | `auth.ts` (createSession, deleteSession): `/dev/switch` in the build, OTP in Stage 10                                                            | no business data; no RLS                                                                         |
| `audit_events`      | One row per authoritative write (I7): actor, kind, table, row, before, after, request id                                                                                                                                                                                                                                                                                 | the `audit_row()` trigger alone (security definer); `ekbill_app` may only read                                                                   | RLS on `business_id` for reads; append-only                                                      |
| `ai_calls`          | Every model call (rule 9, I6): purpose, model, prompt version, input hash, tokens, cost, latency, outcome                                                                                                                                                                                                                                                                | `packages/ai` (Stage 7 onward)                                                                                                                   | RLS on `business_id`, a null row for system calls                                                |

Extensions: `pgcrypto`, `vector`. The tenancy toolkit is `packages/db/tenancy.sql` (included by migration `0001_identity.sql`): `apply_tenancy(table)` adds forced row-level security on `business_id = app_business_id()`, the audit trigger, the delete refusal (8.3) and the model-actor refusal (I6: `app.actor_kind = 'model'` may not write). The application role `ekbill_app` owns nothing; `withTenant()` runs every scoped transaction as it (`SET LOCAL ROLE`) with the scope in `app.business_id`, `app.user_id`, `app.actor_kind`, `app.request_id`. Migration `0002_documents.sql` applies it to `series` and `documents` and adds two triggers on `documents`: `issue_gate` (a row may become `issued` only while `app.issuing = '1'`, a transaction-local setting that `issueDocument()` alone sets) and `immutable_once_issued` (on an issued or cancelled row, number, year, kind, series, date, customer, lines, totals, snapshot, flags, link and issue time never change; status moves only to cancelled; an IRN is written once). A unique partial index on `(business_id, series_id, financial_year, number)` backs the gapless allocation (I3).

## Critical paths

- **Health**: `GET /api/health` (`apps/web/app/api/health/route.ts`) → `schemaStatus()` (`packages/db/src/index.ts`) reads the newest `schema_migrations` tag; reads `BACKUP_STATE_FILE` for the last backup's age. No secrets in the body.
- **Migrations**: container start → `node packages/db/migrate.mjs` → advisory lock 7201019 → each pending `NNNN_*.sql` in one transaction → `schema_migrations` row.
- **A request**: `apps/web/proxy.ts` stamps `x-request-id` → the page or action calls `apps/web/server/session.ts#current()` → `@ekbill/db#resolveScope(sessionId, requestId)` reads `sessions` + `users`, then the active `memberships` row (outside RLS) → `TenantScope { businessId, userId, role, requestId }` → every repository function takes it first and runs inside `withTenant()` (`packages/db/src/scope.ts`).
- **A write**: action validates (zod, `apps/web/actions/schema.ts`) → repository checks `allow(scope, allowedRoles.x)` (I8) → `withTenant()` → the policy fences the rows (I1) → the audit trigger appends the row (I7) → `ActionResult`.
- **Become someone (the build)**: `GET /dev/switch/[person]` (`AUTH_MODE=switcher`) → `createSession()` for the seeded user and their one active membership → the `eb-session` cookie (httpOnly) plus `eb-theme` and `eb-lang` from the user's row → Home, or `/welcome` for the owner with no business.
- **Issue a document** (I2, I3, I4): the action (Stage 6) calls `packages/db/src/repos/documents.ts#issueDocument(scope, { id, today })` → `allow()` (owner or staff) → `withTenant()` → `set_config('app.issuing', '1', true)` → `SELECT … FOR UPDATE` on the draft, then on its series (always that order) → the business row → for a credit note, the linked issued invoice → `packages/engine/src/issue.ts#prepareIssue(draft, seller, customer, GST_RULES, today)` (which runs `tax.ts#computeTax` and `assess.ts#assessDocument`; a blocker ends the transaction with `IssueRefusedError`, no number spent) → `numbering.ts#nextNumberFor` / `afterAllocation` → `UPDATE series` → `UPDATE documents` with the number, the financial year, `issued_at`, the `IssuedSnapshot` (rule pack version, rules applied, seller, customer, lines, totals, legend, linked invoice), the engine's totals and lines → the audit trigger writes two rows under the request id. Everything a customer sees is rendered from `issued_snapshot` (Stage 6), never from the live business or customer row.
- **Set up a business** (Stage 4): `/setup/[step]` keeps the answers in the browser draft; "Chalo, shuru karte hain" → `apps/web/actions/business.ts#finishSetup` → `profileInput` (zod) → for a brand-new owner `businesses.createBusiness(who, profile)` (`checkProfile` in the engine, the row, the owner membership and the two default series in one transaction) then `auth.ts#adoptBusiness(sessionId, userId, businessId)`; for an owner who has one, `businesses.saveProfile`. The drawn signature follows through `setBusinessFile`. Home then shows the first-bill welcome for a business with nothing in it.
- **Save the profile** (Aap): the sheets edit a form the engine checks as the owner types (`checkProfile` in the browser names the field); one sticky Save → `saveProfile` action → `businesses.saveProfile` (the same `checkProfile`, then one UPDATE, one audit row). The look, the logo, the signature and the series save as they are chosen (`saveLook`, `setBusinessFile`, `addSeries`, `changeSeries`, `chooseDefaultSeries`), each its own audited write.
- **A file on the paper**: `PaperData.logoUrl` / `signature` are `/api/files/<id>` URLs; the route resolves the session, reads the row under its scope (`files.getFile`) and serves the bytes with the stored mime, an ETag of the sha256 and `nosniff`.
- **Import old bills** (Stage 5; I6): the import screen posts the picked files to `POST /api/imports` → `imports.startImport` (the files kept as bytes) → `server/queue.ts#enqueue('read-import')` → the worker (`apps/worker/src/import/job.ts`) reads each file (`read-file.ts`: PDF text through pdfjs, CSV and XLSX by their headers, Docling for photos and scans) with the engine's readers (`packages/engine/src/import`) → `imports.recordReading` (one staging row per customer, deduplicated, matched against the business's customers) → the screen, which asked again until the import was read, shows the rows → "N customers add karo" → `commitImport` action → `imports.commitImport` (only the ticked, new rows become customers, in one transaction).
- **Workings** (Stage 8 wires the screen): `workings.ts#outwardDocumentsFromSnapshots(issued rows)` → `buildGstr1({ period, documents })` (B2B, B2C large by the pack's threshold, B2C small, CDNR/CDNUR, HSN summary, document summary, totals, rule ids) and `buildGstr3bOutward`; drafts never reach it, cancelled documents are reported and not counted.

## Tooling

- `npm run watch` (`scripts/watch.mjs`): the 5.2 checks on every save, first red stops; `.watch/status.json`, `.watch/log`. `--once` for CI and before a commit.
- `npm run review:stage -- N` (`scripts/review-stage.mjs`): rule 12. Four inputs, fixed checklist, `docs/stages/stage-N-review-k.md`. `--check-model` confirms `OPENAI_REVIEW_MODEL` resolves; `--dry` builds the prompt without a call.
- `npm run tokens:check`, `rules:check` (every pack entry against `packages/engine/rules/schema.ts`; at most 3 unverified), `rules:verify` (fetches each entry's official source and looks for its `verify.mustContain` phrases; writes `verified`, `verifiedOn`, `verifiedBy`; run where the sites are reachable), `trace` / `trace:check` (→ `docs/FIELD-TRACE.md`), `flow` / `flow:check` (→ `docs/SCREEN-FLOW.md` from `apps/web/screens/*/manifest.ts`).
- `scripts/copy-fonts.mjs` runs before `dev` and `build` of `apps/web`: the pack's `.woff2` files into `apps/web/public/fonts` (gitignored).
- `scripts/local-postgres.sh`: a local Postgres on 5440 with `ekbill2_dev` and `ekbill2_test`.

## Deployment

`deploy/`: one image (`deploy/Dockerfile`), two commands (web server, worker). Compose project **`ekbill2`** (`deploy/docker-compose.yml`): `db` (pgvector/pg16, volume `ekbill2_pgdata`, 127.0.0.1:5441), `docling`, `app` (127.0.0.1:8080), `worker`, `caddy` (80/443, automatic HTTPS, basic-auth gate while sign-in is off). `deploy/vm/up.sh` reads the secrets from Secret Manager and `.env`, hashes the gate password in a throwaway Caddy, and starts the stack. `deploy/vm/backup.sh` (nightly 02:30 IST via `deploy/vm/schedule-backup.sh`) dumps to `gs://<project>-ekbill-backups/pg2/` and writes `deploy/vm/state/last-backup.json` for `/api/health`. `deploy/vm/restore.sh` loads a dump; `deploy/vm/free-space.sh` removes only this project's unused images.

CI (`.github/workflows/ci.yml`): push to `main` and pull requests run `npm run watch -- --once` with a Postgres service, then build and Playwright (phone, both themes; `@slow` excluded). `slow.yml` on `workflow_dispatch`: `@slow` journeys, load (Stage 10), evals (Stage 7).

## Screens (Stage 1, I10)

`apps/web/screens/<id>/` holds each production screen: `manifest.ts` (route, purpose, primary action, taps, states, guide ids, tour, roles, hidden-per-role; `scripts/flow-map.mjs` and `/flow` read it), `data.ts` (a typed loader over `tests/fixtures/v2.json` through `screens/fixtures.ts`; Stages 4–9 re-point it at repositories), `Screen.tsx` (a client component built from `@ekbill/ui`). `apps/web/app/**/page.tsx` are thin: resolve the viewer (`screens/viewer.ts`: the session through `server/session.ts#current()`, with the fixture persona the seeded person maps to; `?as=` is a look for `/flow`), call the loader, render the screen. `screens/shell/AppShell.tsx` is the one shell (top bar, floating tab bar with the mic, Tour button, GuideHighlight). `screens/draft.ts` is the prototype's only memory (sessionStorage behind `useDraft`). `screens/registry.ts` lists every manifest, a sample URL per screen and the extra fixture states; `screens/golden-paths.ts` the tap sequences the tests count.

## What changed in Stage 0

Everything above was created. No product feature, no screen flow (Stage 1).

## What changed in Stage 1

Every screen of master prompt 8.0 as a clickable prototype on fixtures in both themes (25 screens, 22 extra states), the `/flow` review screen, the guide tour on every screen, the golden paths within budget, `packages/engine` ids and money copied from the MVP, 335 copy keys added, six kit components (Sheet, ChoiceList, SettingRow/Group, OtpInput, SearchInput, EmptyState, ProgressLine), `scripts/copy-build.mjs`, `scripts/copy-thumbs.mjs`, `scripts/flow-dump.ts`, `scripts/flow-urls.ts`, `scripts/fixtures-v2.mjs`.

## What changed in Stage 2

Identity, tenancy, roles and audit (migration `0001_identity.sql` from `packages/db/src/schema.ts`, with `packages/db/tenancy.sql` included): users, businesses, memberships, sessions, audit_events, ai_calls; the `ekbill_app` role and `withTenant()`; `resolveScope()`; repositories for businesses, memberships and users with `allowedRoles` on every write; the build seed (three businesses with owner, staff and accountant, one owner without a business; `npm run seed`); `/dev/switch` issues real sessions; theme and language live on the user (`apps/web/actions/user.ts`); the tests `tests/integration/tenancy.test.ts` and `roles.test.ts` are generated by `scripts/gen-tests.mjs` from the repository module list and the `allowedRoles` tables (`gen:check` in the watcher); `audit.test.ts`, `rls.test.ts` (raw connections), `session.test.ts`, `tests/e2e/identity.spec.ts`. ## What changed in Stage 3

## What changed in Stage 6

Bills, money and sharing, wired. Repositories: `payments.ts` (record, write off, reverse; the bill row locked), `reminders.ts`, `document-files.ts`, and in `documents.ts` `listBills` (chips, search, the balance and last payment per row), `billView`, `findBill` (by id or number), `lastBillFor`, `duesToday`; `issueDocument` stamps `customers.last_billed_at`. `packages/db/src/system.ts` lists the businesses with bills for the daily job (ids only, outside any tenant). `packages/render`: the MVP's templates on the issued snapshot (`template.ts`), Chromium with JavaScript off and the network refused (`render.ts`), `printAndKeep` / `printTheRest` (`print.ts`). Web: `actions/bills.ts` (`issueBill`, `cancelBill`, `makeCreditNote`, `recordMoney`, `reverseMoney`, `reminderOpened`), `GET /api/documents/[id]/file` (any member; the accountant's file is printed, not kept), `screens/live.ts` (documents in the fixture shapes the screens draw; a look stays on the fixtures), the eight bill screens and Home, dues, the customer folder and directory on the documents. Worker: `render-other-sizes` after each issue and `dues-today` daily at 08:00 IST (logged; nothing is sent). The seed issues the twenty fixture bills through `issueDocument` with their payments, the cancelled bill and the credit note. Playwright's global setup seeds in its own Node (`tests/e2e/prepare.ts`).

## What changed in Stage 7

Photo → bill. Migration `0006_photo.sql`: `uploads` (the picked photo as it came, never changed), `extractions` (the reading: status pending → ready | failed → reviewed → committed | discarded, the normalised image, the checked result, warnings, the matched customer and score, the ai_calls row, cost and latency, the committed document) and `extraction_corrections` (field, model value, human value; append-only); `guard_extraction` replaces the model-actor refusal on `extractions` with a narrower rule (a model writes a pending reading once and nothing else; only a person commits, and only to an issued bill); the audit trail leaves the image bytes out. `packages/ai` makes its first call: `callVision` (the versioned prompt `prompts/read-bill/v1.md`, the zod answer `readBillAnswer`, a timeout, retries on 429/5xx, one `ai_calls` row per call through the caller's recorder, cost from `OPENAI_VISION_PRICE_IN/OUT`), the OpenAI chat-completions transport, and the fake transport the tests use (`AI_TRANSPORT=fake`). The engine's `read-bill.ts` checks a reading (numbers, quantity × rate, the date, the customer by phone or name, the total by `computeTax`, never the image's). The worker's `read-bill` job normalises the photo with sharp (EXIF upright, ≤ 2000 px, JPEG q85), asks Docling for printed text as a hint where it runs, calls the model with the business's customer and item names, checks and records the reading as the model. Web: `POST /api/photos`, `GET /api/extractions/[id]/image`, `makeBillFromPhoto` (Stage 6's issue path, then the corrections and the commit), the photo screen on a real reading (polls while reading; review with confidences, the match, the totals note; unclear, no bill, unavailable). `npm run eval:read-bill` scores the pipeline on the labelled set (`tests/fixtures/bills/real/`, else the synthetic set from `make-synthetic.mjs`).
